# Current status

## Project state

M0–M4 are complete and merged. The codebase has four independently
compiling COBOL driver programs, a shared copybook, one called subprogram
(now table-driven), and an indexed master file generated by a small
conversion utility. All stages from the original architecture plan are
done; the project is in its M5 documentation pass.

## Features completed ✅

- **M0 — Toolchain setup.** GnuCOBOL 3.2.0 via Homebrew, verified with
  `src/hello.cob` (`cobc -xj`, zero warnings).
- **M1 — Stage 1 (`src/payroll-v1.cob`).** Reads `data/employees.dat`
  (4 fixed-width records), computes gross pay (`hours × rate`), writes
  `data/payroll-report.out` — title, column headers, one detail line per
  employee, total-gross line, employee-count line. Verified by hand:
  total gross `3,871.50`.
- **M2 — Stage 2 (`copybooks/employee-record.cpy` +
  `src/payroll-report.cob`).** Employee record layout extracted to a
  copybook, `COPY`d into both `payroll-v1.cob` and the new
  `payroll-report.cob`. The new program produces a paginated summary
  report in `data/payroll-summary.out`: repeating page/column headers, 2
  detail lines per page, a page break (`WRITE ... AFTER ADVANCING PAGE`,
  confirmed to emit a real form-feed byte) whenever a page fills, grand
  totals at the end. `payroll-v1.cob`'s output was byte-diffed against
  its pre-copybook version to confirm the refactor was behavior-preserving.
- **M3 — Stage 3 (`src/tax-calc.cob` + `src/payroll-net.cob`).** Tax
  withholding moved into its own subprogram, `tax-calc.cob`, with a
  `LINKAGE SECTION` taking gross pay in and returning tax withheld and net
  pay. A new driver program, `payroll-net.cob`, reads the same
  `data/employees.dat` (via the shared copybook), computes gross pay the
  same way Stage 1 does, `CALL`s `tax-calc.cob` per employee, and writes
  `data/payroll-net-report.out` — gross/tax/net detail lines plus three
  grand-total lines and the employee count. Three fictional, hardcoded
  `IF`/`ELSE` tax brackets (10%/15%/20%, thresholds `850.00`/`1050.00`)
  were chosen so all three are exercised against the existing 4-employee
  sample data. Verified by hand: total tax withheld `597.05`, total net
  pay `3,274.45` (`3,871.50 - 597.05`).
- **M4 — Stage 4 (`src/build-employee-index.cob` +
  `src/payroll-indexed.cob`, `tax-calc.cob` updated).**
  `build-employee-index.cob` converts `data/employees.dat` into
  `data/employees-indexed.dat`, an `ORGANIZATION IS INDEXED` file keyed
  by `EMP-ID` (a generated binary artifact, `.gitignore`d rather than
  checked in). `payroll-indexed.cob`, a new driver, opens that file with
  `ACCESS MODE IS DYNAMIC` and demonstrates both a random `READ ... KEY
  IS` lookup (employee 1003, no scan) and a `START` + sequential `READ
  NEXT` pass building the same style of gross/tax/net report as Stage 3,
  written to `data/payroll-indexed-report.out`. `tax-calc.cob`'s
  hardcoded `IF`/`ELSE` tax brackets were replaced with an `OCCURS 3
  TIMES` table walked by `SEARCH` — same thresholds and rates, verified
  byte-identical against Stage 3's checked-in `payroll-net-report.out`
  before and after the change (a `TB-IDX`-not-reset bug was caught and
  fixed during that verification — see STAGE-NOTES.md). Totals match
  Stage 3 exactly: total tax withheld `597.05`, total net pay `3,274.45`.

All four standalone driver programs compile with `cobc -x -Wall -I
copybooks` at zero warnings (`payroll-net` and `payroll-indexed`
additionally need `src/tax-calc.cob` given to `cobc` in the same
invocation, so the `CALL` resolves — see README).

## Recent major changes

- Replaced `tax-calc.cob`'s hardcoded `IF`/`ELSE` tax-bracket logic with
  an `OCCURS`-table + `SEARCH` lookup (Stage 4), verified
  behavior-preserving via byte-diff against Stage 3's output.
- Added `src/build-employee-index.cob`, converting `data/employees.dat`
  to a new indexed master file, `data/employees-indexed.dat` (generated,
  `.gitignore`d, not checked in).
- Added `src/payroll-indexed.cob`, a new Stage 4 driver program
  demonstrating `ORGANIZATION IS INDEXED`, random `READ ... KEY IS`, and
  `START` + `READ NEXT`, writing `data/payroll-indexed-report.out`.
- Documented the Stage 4 build steps, the `SEARCH` vs. `SEARCH ALL`
  choice, and the `TB-IDX` reset bug in README/STAGE-NOTES.

## Open technical concerns

- No automated tests or CI — see
  [architecture.md#known-architectural-debt](architecture.md#known-architectural-debt).
  Acceptable while test data stays small enough to hand-verify.
- `data/employees-indexed.dat` must be rebuilt locally
  (`./build-employee-index`) before `payroll-indexed` will run — it isn't
  checked in, since it's a generated, GnuCOBOL/platform-specific binary
  file rather than portable plain text.
